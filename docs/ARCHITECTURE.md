# 架构说明

> 面向接手这份代码的人：为什么这样分层、规则为什么长这样、哪些地方改动代价很高。

## 一、为什么要分两层

这个项目有两类内容，方向相反：

- **通用能力**——界面、规则、接口、字段结构。任何人填进自己的课表和目标就能用，应该能公开、能分发。
- **具体某个人的学业记录**——真实课程与考期、专项目标、每天的真实投入。一旦泄露就是隐私事故。

早期版本把两者焊在同一个 HTML 里：课程名写死在常量里，标题栏印着学校与专业，数据存在一个公共路径。
结果是想看代码就得连个人目标一起看，想用工具就得先把别人的课程删干净。

拆分后的判断标准只有一句：**换一个人来用，这条内容还要不要变？**

- 要变 → 公用层 `core/`
- 不变，只对某个人成立 → 私有层 `private/`

`core/` 是一条硬边界：**不许出现真实课程名、真实日期、真实姓名**。出现即视为越界，因为它会被一起交出去。

个人资料字段（`meta.owner` / `school` / `major` / `grade` / `semester` / `goal`）在公用配置里全部为空串。
不是「默认值无害」，而是「默认值会冒充使用者的输入」——它会让页面看起来像已经填好了，
也会让别人的名字出现在你的页面上。身份备注是否显示由 `meta.showIdentity` 控制，默认 `false`。

## 二、目录职责

| 位置 | 职责 | 约束 |
| --- | --- | --- |
| `core/domain/` | 规则、统计、数据模型、日期、文本、主题清单 | 纯函数：不读全局、不碰 DOM、不读系统时间；`today` 由调用方传入 |
| `core/web/app.js` | 渲染与交互 | 只通过薄包装访问 domain，不复制规则 |
| `core/web/app.css` | 样式 | 独立文件，便于替换主题 |
| `core/web/index.html` | 结构 | 只有标签与 script 引用 |
| `core/server.js` | 接口与鉴权 | `import` 同一个 domain，不自己维护 `emptyDB` / `normalize` |
| `core/default-profile.json` | 公开占位方案 | 克隆下来改这一个文件即可上手 |
| `private/` | 使用者的真实数据、口令、地址 | 永不外发，`.gitignore` 已排除 |

### ES Modules 的选择

`core/package.json` 写了 `"type": "module"`，于是 `core/` 内的 `.js` 就是 ES 模块：
浏览器能直接 `import`，Node 端也是同一个 `import`，**不需要构建，也不存在「浏览器一份、Node 一份」**。

代价是：模块作用域下 HTML 的内联 `onclick` 看不见模块里的函数，
所以 `app.js` 必须把需要暴露的函数显式挂到 `window` 上。这是有意的取舍，不是遗留问题。

同理，页面不能用 `file://` 双击打开——模块脚本被同源策略拦住，必须起 HTTP 服务。

## 三、规则引擎

`buildAnalysis(db, profile, records, today, ui)` 是**唯一实现**：页面调它，`GET /api/analysis` 也调它。

三条约束：

1. **纯函数**。不读全局、不碰 DOM、不读系统时钟。`today` 作为参数传入。
   这样它可以被单测逐字比对，也能被定时任务复用。
2. **输出结构固定**：`analyses`（结论，含 HTML 与纯文本两版）+ `acts`（行动，最多三条）。
3. **第五个参数 `ui` 可选**：不传 = 全开（向后兼容，测试里有专门一条守着），
   传了就把被关掉的模块整段跳过。这是「关掉 ≠ 藏起来」的实现位置——
   只把输入框 `display:none` 而规则照旧提醒，第二天会得到一条针对刚刚关掉的模块的催命提示。

阈值（作业优先、周负荷、断层天数、连续无休等）来自真实使用中的反复校准，改之前先想清楚副作用：
它们互相耦合，抬高一个阈值往往会让另一条建议消失。

## 四、访问控制

请求分三档：

| 路径 | 是否公开 | 说明 |
| --- | --- | --- |
| `/`、`/index.html`、`/app.css`、`/app.js` | 公开 | 只有通用界面 |
| `/domain/*` | 公开 | 共享模块，只含规则与工具 |
| `/api/health` | 公开（分档） | 有口令返回条数与方案来源；无口令全部 `-1` / `hidden` |
| `/api/data`、`/api/profile`、`/api/analysis` | 需口令 | 无口令 401 |
| `/profile.js`、`/brief.js` | 需口令 | 无口令返回 `window.__AUTH__ = false` |
| `/private/*`、`../private/*` | 403 | 静态目录不覆盖私有目录，路径穿越也拦住 |

口令机制：

1. 口令来源：环境变量 `LEDGER_TOKEN` → `private/config.json` 的 `token` → **首次运行自动生成**
   （`crypto.randomBytes` 取 16 位，字母表去掉 `0/O/1/l/I`，手机手输不出歧义）。只在启动时读一次进内存。
2. 首次用 `?k=<token>` 打开，服务端种 30 天 HttpOnly Cookie，之后同浏览器不再需要带参数。
3. 比对用 `crypto.timingSafeEqual`（定长比较），不泄露「第几位开始不同」。
4. 同一来源 10 分钟内错 30 次 → 锁 10 分钟（429）。
5. **先认口令再谈封禁**：口令正确的人不受封禁连坐，否则共用出口 IP 会把自己锁在门外。
6. `Cookie` 的 `Secure` 只在确实走了 HTTPS（`x-forwarded-proto: https`）时添加——
   本地 http 加了会导致 cookie 根本不发出去。
7. **默认不开放**：什么都没有时生成口令而不是裸奔——发布包不带 `private/`，
   若「无口令 = 开放」，任何人解压启动的第一秒就在局域网里敞着。要开放必须
   显式 `LEDGER_OPEN=1`，此时启动日志写 `access 开放模式`。
8. 换口令改 `config.json` 后必须重启；删掉 `token` 字段的效果是「下次启动重新生成」，
   不是变成开放模式。写不进 `config.json`（只读目录）时口令只留在内存，日志会喊一声。

### 监听范围

两条启动路径的默认值不同，是刻意的：

- `core/server.js`（`npm start`）默认 `127.0.0.1`——只有本机能访问。
- `launch.js`（`start.bat`）默认 `0.0.0.0`——同一 WiFi 的手机可以直接连，口令是唯一的门。
- 公网隧道默认不建，`LEDGER_TUNNEL=1` 才开；`LEDGER_NO_TUNNEL=1` 强制关闭。

单独起服务时保守、双击启动时方便。改动前先想清楚「要让谁能连」。

## 五、接口清单

| 方法 | 路径 | 权限 | 作用 |
| --- | --- | --- | --- |
| GET | `/api/health` | 公开（分档） | 存活检查、条数、方案来源 |
| GET | `/api/data` | 口令 | 读整份记录 |
| POST | `/api/data` | 口令 | 写入，见下节并发语义；请求体超 2 MB → 413 |
| GET | `/api/profile` | 口令 | 读方案（私有优先，回落到公用占位） |
| POST | `/api/profile` | 口令 | 合并写入方案，保留由规划流程维护的字段 |
| GET | `/profile.js` | 口令 | 把方案注入成 `window.__PLAN__` |
| GET | `/brief.js` | 口令 | 当晚提醒正文（包装自 `private/brief.json`） |
| GET | `/api/analysis?date=` | 口令 | 跑一遍规则，返回 analyses / acts |

方案走 `<script src>` 而不是异步请求，是为了让首屏渲染时 `PLAN` 已经就位——
规则函数大量同步读 `PLAN.courses`，异步会引入一整类「先渲染空再跳变」的时序 bug。

## 六、并发写入

旧机制是「整份覆盖 + 比 `meta.updatedAt`」：手机记今天、电脑补昨天，后提交的那次会抹掉另一份整天。

现在客户端提交时带上 `baseUpdatedAt`（「我这份底稿基于哪一版改的」）：

- 底稿 == 磁盘 → 直接覆盖（快路径，多一次比较而已）
- 底稿 != 磁盘 → 服务端 `mergeDBs()` 按日期键、周键、作业 `id` 逐条合并，有 `ts` 就新者胜，回传合并结果
- 不带 `baseUpdatedAt` 的老客户端 → 仍走原来的 409 防倒退，不会被新逻辑搞坏

再叠一层兜底：磁盘上有记录、提交的却整份是空的（本地存储被清、没拉到数据就提交），
**拒绝抹除，改为合并**。这一条抓到过真实风险——快路径完全一致时，空提交本来真的会清库。

删除语义仍是弱点：合并求并集，删掉的一天或一条作业会被另一端带回来。
单用户单端为主，暂不引入墓碑（tombstone）机制。

## 七、传输层

| 资源 | `Cache-Control` | 压缩 | 说明 |
| --- | --- | --- | --- |
| `fonts/*.woff2` | `public, max-age=2592000` | 否 | 二进制已压过，再压是浪费 CPU |
| `app.js` / `app.css` / `domain/*.js` | `no-cache` | gzip | 带 `ETag`，命中走 304 |
| `index.html` / `/` | `no-cache` | gzip | `no-cache` ≠ 不缓存，是「每次都用 ETag 复验」 |

gzip 结果按「路径 + mtime + size」缓存在内存（`gzCache`），不重复压同一份；
`Vary: Accept-Encoding` 保证中间缓存不会把压缩体发给不支持的客户端。
实测 `app.js` 70 KB → 24 KB。

### 字体

界面声明了像素字体 Zpix，但**仓库不包含任何字体文件**：

```css
@font-face{
  font-family:"Zpix";
  src:local("Zpix"),local("Zpix12"),local("Zpix Pixel"),local("Zpix Regular");
}
```

只用 `local()` 源，含义是「本机装了就用，没装就回退到 `--font` 栈里的系统字体」。
好处有三点：零网络请求、不会有 404、许可上与第三方字体彻底解耦
（Zpix 禁止再分发与拆分，见 [NOTICE](../NOTICE.md)）。

代价是字形随机器而变：装了 Zpix 是像素风，没装是普通中文字体。
布局与配色不受影响，但**改版式时要在两种字体下各看一眼**——中文字体宽度差异可能触发换行。
`test/browser-check.mjs` 里有一条断言守着「字体栈没有失效」，但不断言具体是哪个字体。

## 八、界面开关

| 层 | 存在哪 | 谁改 | 关掉的效果 |
| --- | --- | --- | --- |
| 页签 | `ui.tabs[id]` | 设置页勾选框 | 导航栏收起该页，`switchTab()` 也拒绝跳进去 |
| 模块 | `ui.modules[id]` | 设置页勾选框 | 页面里某一块收起（睡眠、卡点、专项…） |
| 规则 | 同 `ui.modules[id]` | 无需单独配置 | `buildAnalysis()` 第五参数，关掉的模块不再出结论 |

清单只写在 `core/domain/ui.js`（`TABS` / `MODULES`），页面、规则、测试三处都从这里读。
新增一个可关项 = 在那两个数组里加一行。

三个刻意的取舍：

1. **设置页不能被关掉。** 否则把页签全关掉之后就再也没有入口改回来——一个能把自己锁死的开关不是开关。
2. **关掉不是藏起来。** 见 §3 的第五参数。
3. **现改现生效，落盘是第二步。** 点保存时先本地重排，再 `POST /api/profile`；
   反过来的话网络慢一点就会有半秒钟页面还是旧样子。没有服务端时也会改，但明确说明「没写进文件」。

## 九、迁移与回滚

- 旧数据：`data/records.json` 自动合并进 `private/records.json`，原件备份保留。
  迁移用标记文件 `.migrated-v1`：决策一旦做出（哪怕结论是「不用合并」）就落标记，
  避免旧文件被恢复回来时二次合并。
- 回滚：把 `private/` 换成旧备份，用旧版 `server.js` 起服务即可。
  页面认 `window.__PLAN__`，旧版没有这个注入时会落到占位方案，不会白屏。
- 关闭口令：`LEDGER_OPEN=1` 重启（**不要在有真实数据时这么做**）；只删 `token` 字段不行，
  那只会让下次启动重新生成一个。

## 十、已知限制

1. **口令是唯一凭证**，没有账号体系。地址 + 口令一起泄露就等于全公开。
2. **数据只有一份**。分层解决的是「谁能看」，不解决「丢了怎么办」——定期导出仍是必须的。
3. **单实例假设**：一个进程对应一个 `private/`。多份数据靠 `LEDGER_PRIVATE_DIR` 起多个进程，
   而不是在同一个进程里做多租户（那会引入鉴权、配额、隔离一整套复杂度）。
4. **里程碑与周任务不能在界面手改**：它们是规划判断的产物，手改容易和规则脱节。
5. **删除不传播**（§6）。
6. **`file://` 不可用**（§2）。
